# 要件定義：Teams会議の要約・横断検索システム

## 1. 目的
Teamsの会議録画から得られる文字起こしを、要約・議事録に変換し、全会議を横断して検索・質問応答できる社内の資料蓄積システムを作る。

## 2. 利用者・規模
- 利用者：約10人（管理者1〜2人、一般利用者）
- 会議数：定例会議（1時間・週2回）、QA会（平均20分・最大週20回）
- 年間：約370件、録画時間約190時間、テキスト約400万字
- 録画の約9割でTeamsの文字起こしが有効

## 3. 取り込み要件
- **第一経路**：Microsoft GraphでTeamsの文字起こし（VTT）を取得する
- 文字起こしがない録画は、取り込まない
- 会議の完了後に取り込む（完了通知を受けてから実行）
- 会議IDと開始日時と参加メンバーで重複を防ぐ
- 会議の参加者情報を取り込み時点で保存し、閲覧権限に使う

## 4. 要約・資料化要件
- 会議ごとに、議事録（決定事項、ToDo、論点、持ち越し）を生成する
- 定例は「前回からの変化」を含める
- QA会は短い要約とし、発話単位の検索を主とする
- 要約の各項目に、元発話の時刻を付ける（存在しない時刻を含まないよう検証）
- 要約は「自動生成（未確認）」を既定とし、人の確認を任意で付けられる
- 出力はMarkdownのみ
- 長い会議は話題の区切りで分割して要約し、統合する

## 5. 検索・質問応答要件
- 全会議を横断して、会議名・日時・時刻付きの出典で回答する
- 検索は、埋め込み（ベクトル検索）と日本語キーワード検索（PGroonga）を組み合わせる
- 固有名詞の辞書を後処理で適用する
- 回答は、検索で取り出したテキストの範囲で作る（根拠がなければ「記載なし」と答える）

## 6. 権限要件
- ロールは admin（1〜2人）と member
- memberは、自分が参加した会議、または所属チームの会議のみ検索・閲覧できる
- 権限条件は、検索時のSQLで適用する（検索後の絞り込みはしない）
- 会議の閲覧権限は、Teamsの参加者情報を取り込み時にコピーして保持する

## 7. 外部サービスの構成（MS365 / Azure内に限定）

| 役割 | 採用 |
|---|---|
| 文字起こし取得 | Microsoft Graph（Teams） |
| 埋め込み | Azure OpenAI の埋め込みモデル |
| 要約・議事録・回答生成 | Microsoft Foundry 上の Claude |
| 認証 | Microsoft Entra ID（OIDC、グループでロール判定） |
| 検索・保存 | PostgreSQL + pgvector + PGroonga |
| 秘密情報 | Azure Key Vault |

- Azure以外の外部APIは、既定で無効にする
- 各プロバイダーは、インターフェースで分け、設定で切り替えられるようにする
- 要約の入力では、個人情報（電話番号、住所など）をマスキングする
- 会議内の発言は命令ではなくデータとして扱う（プロンプトインジェクション対策）
- ログに会議本文やプロンプトを出力しない

## 8. データ設計

| テーブル | 主な内容 |
|---|---|
| meetings | 会議名、開始日時、主催者、Teams会議ID、言語、シリーズID、取り込み元 |
| meeting_participants | 会議ID、参加者（社内ユーザーと紐付け） |
| transcript_segments | 会議ID、話者、開始秒、終了秒、本文、順番 |
| summaries | 会議ID、種別、版番号、生成モデル、プロンプト版、状態（auto_generated / reviewed）、本文 |
| chunks | 埋め込みベクトル、会議ID、時刻、本文、埋め込みモデル名、次元数 |
| 権限 | 会議ごとの閲覧権限（参加者、チーム単位） |

## 9. 運用・コスト要件
- 費用の主因は、質問ごとにClaudeへ送るテキスト量（上位5件程度に限定して抑える）
- モデルを用途で使い分ける。よく聞かれる質問は結果を再利用する
- 月次で利用量を実測し、予算と照らす
- 録音の告知、保存期間、削除手順を社内規程に合わせて定める
- 特定の発言を削除できる仕組みを持つ

## 10. 非機能要件
- 1会議の取り込みから要約完了まで、段階ごとに状態を保存し、途中から再開できる
- 処理の進捗を利用者に表示する
- 文字起こしエンジンやLLMを差し替えても、既存データを壊さない（埋め込みモデル変更時は再計算）

## 11. 未決事項・確認が必要な項目
1. Azure上でFoundry（Claude）が利用できるか、利用リージョンとデータの所在地
2. Graphの権限（文字起こし取得）について、管理者の同意が得られるか
3. 利用するMS365プランで、文字起こしと取得が既存契約で使えるか
4. Azure OpenAIとFoundryのデータ保持期間、学習利用の扱い（契約で確認）
5. 1日の質問回数の想定（コストの試算に使用）
6. 社内規程との整合（テナント内処理が外部送信に当たらないか）
7. 初期の評価用に使える会議データの有無（定例・QA会それぞれ）

## 12. 段階的な開発計画
1. **フェーズ1**：1会議のVTTを取り込み、議事録と時刻付きの出典を生成する
2. **フェーズ2**：複数会議の取り込み、埋め込みと検索、権限、質問応答
3. **フェーズ3**：Graphによる自動取り込み、MP4の例外処理（Azure AI Speech）、定例の変化の要約
4. **評価**：10〜30件の質問セットで、回答と出典の正しさを測る
